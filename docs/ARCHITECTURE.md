# 아키텍처 설명

원본 아키텍처 설명 문서의 내용을 Markdown으로 옮겼습니다. 마지막 절은 향후 개선 계획입니다.

## 중앙 지휘 없이 확장되는 유닛 아키텍처

플레이어와 AI는 실행 순서를 직접 지휘하지 않고 담당 컴포넌트에 행동 의도만 전달합니다. 입력을 받은 컴포넌트가 자신의 행동을 수행하며 공유 데이터를 갱신하면, UnitStateController가 갱신된 데이터를 우선순위에 따라 해석하여 현재 상태를 결정하고 변경 결과를 이벤트로 전파합니다. 이후 각 컴포넌트가 변경된 상태를 자신의 역할에 맞게 해석하여 동작합니다.

상태를 이동·행동·상태 효과의 세 가지 채널로 분리하여 서로 다른 상태가 동시에 존재할 수 있도록 설계했습니다. 이를 통해 공중 공격, 대시 공격, 슈퍼아머처럼 여러 행동과 효과를 자유롭게 조합하면서도 상태 조합의 복잡성과 중앙 관리자의 비대화를 방지했습니다. 새로운 기능 역시 기존 실행 흐름을 크게 수정하지 않고 담당 컴포넌트를 추가하거나 확장하는 방식으로 구현할 수 있습니다.

## 데이터만 추가해 확장되는 스킬 아키텍처

스킬 입력이 들어오면 UnitSkillController가 선택된 SkillDataObject를 현재 스킬로 등록합니다. 이후 각 컴포넌트는 현재 스킬 데이터에서 자신에게 필요한 정보만 해석합니다.

애니메이터는 모션 클립을, 이동 컴포넌트는 이동 배율과 대시 속성을, 스킬 판정기는 공격 범위·판정 형태·투사체 속도를, 사운드와 이펙트는 각 연출 데이터를 사용합니다.

이를 통해 스킬마다 별도의 실행 코드를 작성하지 않고도 ScriptableObject에 데이터를 설정하여 서로 다른 모션, 타이밍, 판정 범위, 이동 방식과 연출을 가진 스킬을 유닛에 조합할 수 있도록 설계했습니다.

## 동작 예시: 대시 입력 처리

플레이어 또는 AI가 UnitMoveController에 대시를 요청합니다.

UnitMoveController는 쿨타임, 공중 대시 횟수, 현재 행동 상태와 스킬의 대시 허용 여부를 검사합니다.

Hit처럼 대시가 불가능한 상태라면 요청을 즉시 종료합니다.

이 경우 UnitStateData가 변경되지 않으므로 Dash 상태가 결정되지 않고, 상태 변경 이벤트도 전파되지 않습니다.

모든 조건을 통과한 경우에만 대시 정보를 공유 데이터에 기록합니다.

UnitStateController가 갱신된 데이터를 해석하여 Dash 상태를 결정하고 이벤트로 전파합니다.

## 상태 전파 예시: 대시 상태에 대한 반응

Dash 상태가 확정되면 입력 처리부가 각 기능을 직접 호출하지 않아도 상태를 전달받은 컴포넌트들이 자신의 역할을 수행합니다.

UnitMoveController: 대시 방향과 속도에 따라 이동

UnitAudioController: 대시 사운드 재생

UnitAfterImageController: 대시가 유지되는 동안 잔상 생성

UnitSkillLauncher: 근접 공격 스킬을 사용 중이라면 대시 공격 판정 활성화

상태 전파는 특정 반응 컴포넌트의 존재를 전제로 하지 않습니다. UnitAudioController가 없으면 사운드만, UnitAfterImageController가 없으면 잔상만 제외될 뿐 대시 상태와 이동은 정상적으로 동작합니다.

따라서 유닛마다 필요한 기능만 선택적으로 조합할 수 있으며, 이동이나 공격 판정처럼 게임 규칙을 수행하는 기능만 필수 컴포넌트로 구성할 수 있습니다.

입력은 하나의 담당 컴포넌트에 행동 의도만 전달합니다. 상태 컨트롤러는 공유 데이터를 해석해 확정된 상태 변화만 전파하며, 별도의 중앙 오케스트레이터 없이 서로를 직접 참조하지 않는 컴포넌트들이 각자의 역할에 맞게 반응하여 하나의 완성된 동작을 구성합니다.

## 향후 리팩터링 방향

현재는 UnitStateData의 변경 사항을 프레임 단위로 해석하여 상태를 결정하기 때문에, 상태가 확정되기 전의 입력 충돌이나 물리 변화를 처리해야 하는 일부 구간에서는 컴포넌트가 확정 상태가 아닌 런타임 데이터를 직접 확인하고 있습니다.

향후에는 상태 공급자만 런타임 데이터를 변경할 수 있도록 권한을 분리하고, 데이터 변경이 완료되는 즉시 UnitStateController가 상태를 평가·전파하도록 개선할 계획입니다. 이를 통해 일반 컴포넌트는 런타임 데이터를 직접 판단하지 않고 확정된 상태와 변경 이벤트만 해석하도록 구성하여, 상태 변경 시점을 일관되게 만들고 컴포넌트의 역할과 상태 변경 원인을 더욱 명확하게 추적할 수 있도록 확장하고자 합니다.
