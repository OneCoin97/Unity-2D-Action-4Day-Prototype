# Unity 2D Action Prototype — 4일 개발

4일 동안 제작한 PC용 2D 플랫폼 액션 전투 프로토타입의 코드 포트폴리오입니다. 이동·점프·대시, 근접 전투와 스킬, 패링, 적 AI와 웨이브 진행을 하나의 플레이 흐름으로 구성했습니다.

**이 저장소는 C# 스크립트와 아키텍처 설명을 담은 코드 포트폴리오입니다.** 설계 설명은 이 README에 모았습니다. 씬·프리팹·외부 에셋을 포함하지 않아 복제만으로 게임을 실행할 수는 없습니다.

## 구현 범위

- **조작:** 이동, 점프, 대시, 일반 공격, 강공격, 공중 내려찍기, 체력 회복, 패링.
- **전투:** 근접·투사체 판정, 피해·회복, 피격 경직과 넉백, 슈퍼아머.
- **적:** 공통 유닛 구조를 사용하는 근접·원거리·순찰·보스 행동.
- **진행:** 스테이지 데이터에 따른 적 생성, 웨이브 진행, 게임 오버·클리어 이벤트, 재시작.
- **피드백:** 공격·피격 이펙트와 사운드, 대시 잔상, 카메라 흔들림, 체력 표시.
- **재사용:** 유닛, 스킬 판정 오브젝트, 이펙트와 플로팅 메시지의 풀 구성.

3. [UnitStateController](Scripts/Runtime/%28Main%29UnitSystem/Control/UnitStateController.cs): 이동·행동·상태 효과의 평가와 변경 이벤트.
4. [SkillDataObject](Scripts/Runtime/%28Main%29UnitSystem/Data/Skill/SkillDataObject.cs) / [UnitSkillController](Scripts/Runtime/%28Main%29UnitSystem/Control/UnitSkillController.cs): 스킬 데이터와 실행 흐름.
5. [UnitSkillLauncher](Scripts/Runtime/%28Main%29UnitSystem/Components/Combat/UnitSkillLauncher.cs) / [UnitSkillEngine](Scripts/Runtime/%28Main%29UnitSystem/Components/Combat/UnitSkillEngine.cs): 근접·투사체 판정의 준비, 실행과 반환.
6. [StageController](Scripts/Runtime/StageSystem/Core/StageController.cs) / [UnitController](Scripts/Runtime/StageSystem/Unit/UnitController.cs): 웨이브 진행과 유닛 생성·반환.

## 설계 포인트

### 공통 유닛과 역할별 컴포넌트

**컴포넌트 패턴을 사용해 이동·점프·공격 판정·피격·애니메이션·사운드·이펙트를 각각 별도 기능으로 분리했습니다.** 플레이어와 적은 유닛에 필요한 컴포넌트를 조합해 구성하고, 같은 기능은 공통 실행 구조를 사용합니다.

플레이어는 **키보드 입력**을 받아 이동·점프·대시·스킬 등의 요청을 담당 컴포넌트와 스킬 컨트롤러에 전달합니다. AI는 **상태 머신에서 순찰·추적·공격 등의 행동을 판단**하고, 그 결과를 같은 방식으로 전달합니다. 입력의 출처가 달라도 실제 이동이나 전투 기능은 공통으로 사용할 수 있도록 구성했습니다.

요청을 받은 컴포넌트는 현재 행동 상태와 쿨타임 등 실행 조건을 확인하고, 요청이 허용되면 자신이 담당하는 행동 정보를 **공유 런타임 데이터인 `UnitStateData`에 기록**합니다. 예를 들어 이동 컴포넌트가 대시 요청을 받으면 대시 가능 여부를 검사한 뒤, 대시 여부와 방향을 런타임 데이터에 반영합니다. 이후 행동이 진행되거나 종료될 때도 해당 데이터를 갱신합니다.

유닛별 중앙 상태 관리자인 **`UnitStateController`는 각 기능이 갱신한 런타임 데이터를 프레임마다 확인하고, 우선순위에 따라 유닛의 현재 상태를 결정합니다.** 상태가 달라지면 현재 상태를 변경하고, 변경된 상태를 이벤트로 각 컴포넌트에 전달합니다.

각 컴포넌트는 전달받은 상태에 따라 자신이 관리하는 기능을 실행합니다. Dash 상태가 전달되면 이동 컴포넌트는 대시 방향과 속도에 맞춰 유닛을 이동시키고, 사운드 컴포넌트는 대시 사운드를 재생하며, 잔상 컴포넌트는 대시가 유지되는 동안 잔상을 생성합니다. 공격 판정 컴포넌트는 근접 공격 스킬을 사용 중이고 대시 공격 조건을 충족하면 공격 판정을 활성화합니다.

**입력과 AI 판단 → 기능별 요청 처리 및 런타임 데이터 갱신 → 중앙에서 상태 결정·변경 → 이벤트로 상태 전달 → 각 컴포넌트의 기능 실행**으로 흐름을 구성했습니다. 이를 통해 입력 방식과 기능 구현의 책임을 나누고, 유닛마다 필요한 기능을 조합할 수 있도록 했습니다.

사운드나 잔상 컴포넌트가 없는 유닛은 해당 연출만 제외되며, 대시 상태와 이동은 유지됩니다. 각 유닛은 게임 규칙에 필요한 기능을 갖추고, 연출 기능은 선택적으로 조합할 수 있습니다.

### 상태를 세 채널로 분리

| 채널 | 표현하는 내용 | 현재 값의 형태 |
| --- | --- | --- |
| Movement | 이동, 점프, 낙하, 벽 접촉, 대시 | 우선순위에 따라 선택한 단일 상태 |
| Action | 공격 준비·실행·후딜레이, 피격, 패링, 사망 | 우선순위에 따라 선택한 단일 상태 |
| Status | 슈퍼아머, 패링 성공 | 동시에 적용 가능한 복합 플래그 |

이동과 공격을 별도로 표현해 공중 공격이나 대시와 공격 판정이 결합되는 동작을 구성합니다.

### 데이터 기반 스킬

`SkillDataObject`에 타이밍, 애니메이션, 이동 제약, 슈퍼아머, 판정, 사운드와 이펙트를 모았습니다. 스킬 입력이 들어오면 `UnitSkillController`가 선택한 스킬을 현재 스킬로 등록하고, 각 컴포넌트는 현재 스킬에서 자신에게 필요한 데이터를 해석합니다.

애니메이션 컴포넌트는 모션 클립을, 이동 컴포넌트는 이동 배율과 대시 속성을, 공격 판정 컴포넌트는 판정 형태·범위·투사체 속도를 사용합니다. 사운드와 이펙트 컴포넌트도 같은 스킬 데이터에서 각 연출 정보를 가져옵니다.

공통 실행 구조가 지원하는 범위에서는 데이터를 설정해 스킬의 모션·타이밍·판정·연출을 바꿀 수 있습니다. 새로운 행동 규칙은 실행 구조 확장이 필요합니다.

## 현재 한계와 개선 계획

현재 상태 평가는 프레임 단위입니다. 런타임 데이터와 확정 상태의 갱신 시점에 차이가 있어, 일부 컴포넌트는 입력 충돌이나 물리 처리를 위해 런타임 데이터를 직접 확인합니다.

다음 리팩터링에서는 상태 공급자만 런타임 데이터를 변경하도록 쓰기 권한을 분리하고, 데이터 변경 완료 후 즉시 상태를 평가·전파하는 흐름을 만들 계획입니다. 일반 컴포넌트는 확정된 상태와 변경 이벤트를 중심으로 동작하도록 정리해, 상태 변경 원인과 반영 시점을 명확하게 만들고자 합니다. **이 항목은 개선 계획이며 완료된 기능이 아닙니다.**

## 구성

```text
Scripts/
  Runtime/
    (Main)UnitSystem/     # 공통 유닛, 입력, 상태, 스킬, 기능별 컴포넌트

    PresentationSystem/  # 이펙트, 메시지, 카메라
    Environment/         # 단방향 플랫폼
```
